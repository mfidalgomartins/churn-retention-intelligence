# Quality and Security Gates

Run these checks before publishing a dashboard or report artifact:

```bash
make quality
```

`make quality` is the release-quality gate. It must pass locally before a
release branch is merged and passes in CI on every pull request and push to
`main`.

| Gate | Command | Blocks on |
|---|---|---|
| Lint | `make lint` | Ruff errors in `src/` or `tests/` |
| Format | `make format-check` | Python formatting drift in `src/` or `tests/` |
| Types | `make typecheck` | mypy type errors in the `churn` package |
| Coverage | `make coverage` | Test failures or coverage below `tool.coverage.report.fail_under` |
| Security | `make security` | Bandit findings in `src/` or vulnerable installed packages |

## Current thresholds

| Control | Source | Current value |
|---|---|---|
| Python runtime | `pyproject.toml` | `>=3.11`; CI builds on 3.12 and tests compatibility on 3.11/3.14 |
| Dependency resolution | `requirements.lock` | Exact release and quality environment used by local install and CI |
| Ruff target | `pyproject.toml` | `py311`, line length 100 |
| Coverage source | `pyproject.toml` | `src/churn` package |
| Coverage threshold | `pyproject.toml` | 80% branch coverage report gate |
| Type checking | `pyproject.toml` | mypy over the `churn` package; `py.typed` ships with the package |
| Bandit scope | `pyproject.toml` | `src/`, excluding generated/build/test paths |
| Dependency audit | `Makefile` | `pip_audit --skip-editable` |
| Vendored JS manifest | `config/vendor_assets.json` | Version, source, license, and SHA-256 |
| Data contracts | `config/contracts/data_contracts.json` | Required columns, primary keys, domains, numeric ranges, date order, and foreign keys |
| Model quality | `config/modeling.yml` | Out-of-time discrimination, Brier score, calibration intercept/slope, and probability bounds |
| Experiment quality | `config/experiments.yml` | Arm size, allocation, baseline balance, assignment/outcome integrity, and saved-MRR identity |
| Monitoring | `config/monitoring.yml` | Complete-period transitions, calibration, drift, and alert schema |

## Coverage scope

Coverage is measured on the reusable analytical code under `src/churn`.
The static chart pack (`graphs.py`) and PDF renderer (`report.py`) are excluded
from the threshold because they are artifact builders with high visual layout
surface and low reusable business logic. The simulator and profiler are also
excluded. Reusable validation helpers remain in coverage; I/O orchestration and
all artifact builders are exercised by the integration suite and `make release`.

## Security scope

Bandit scans application code only. Generated artifacts, tests, build outputs,
and the virtual environment are excluded. Dependency audit runs against the
installed environment and should be rerun after dependency upgrades.
Runtime dependencies include compatible upper bounds in `pyproject.toml` to
reduce accidental major-version drift. `requirements.lock` additionally fixes
the environment used to reproduce published artifacts.

Vendored frontend assets are tracked in `config/vendor_assets.json`; the test
suite verifies the declared SHA-256 hash and package version against the file
under `assets/vendor/`.

Do not commit secrets, credentials, customer data, or private connection
strings. Production adapters publish to ignored `data/` and `outputs/tables/`
paths only; verify Git status before every commit. Connection strings must be
provided through environment variables or repository secrets.

## Evidence to retain

For a production release, retain:

- CI run URL for the commit being released.
- `outputs/tables/release_readiness_matrix.csv`.
- `outputs/tables/final_validation_issues.csv`.
- `outputs/tables/model_performance.csv`, `intervention_balance.csv`, and
  `monitoring_alerts.csv`.
- The immutable snapshot manifest and archive SHA-256.
- The dashboard and report artifacts generated by the same commit.

## Release rule

Do not publish a new release if `make quality` fails. Fix the failing gate,
regenerate artifacts with `make release`, rerun `make quality`, and verify CI is
green for the final commit.
